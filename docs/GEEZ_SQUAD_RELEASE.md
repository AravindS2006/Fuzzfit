# Geez Squad coaching and accuracy release

## Reference and decisions

The [LearnOpenCV demonstration](https://learnopencv.com/ai-fitness-trainer-using-mediapipe/) uses MediaPipe with a squat-specific movement sequence, camera orientation checks, and separate correct/incorrect counters. Its example thresholds are heuristic. Geez Squad keeps exercise-specific start–movement–endpoint–return validation, rather than copying the example's squat thresholds into every exercise. Inactivity must not erase saved workout totals. Camera instructions depend on the selected exercise.

[Google's Pose Landmarker guide](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker) documents 33 landmarks and image/world coordinates. The browser implementation runs inference in a worker. Heavy is the initial model choice; five consecutive inference times above 200 ms switch to Full with an explanation in tracking settings. The [MediaPipe model evaluation](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose.md) favors Heavy on its published benchmark, which is not a measurement of Geez Squad on users' phones.

## Implementation

- Return ownership of the input image bitmap from the worker to the renderer. Draw that image and its corresponding native landmarks together, then release the bitmap. Reject stale results and release their bitmaps too. The meeting's published camera stream remains independent of the local annotated display.
- Keep native temporal tracking, visibility/presence gates, adaptive movement-signal smoothing, aspect-correct image angles, validated world geometry, locked limb/source during a cycle, state transitions, hysteresis, observed range, duration, cooldown and completed-rep quality. Rule version `profile-v4` distinguishes this release from historical scoring.
- A single noisy form frame no longer poisons a completed movement. Bad-form intervals require consecutive observations; reject when they total at least 150 ms and at least 20% of the observed cycle. Sustained poor posture, impossible motion, partial range, missing return movement and low-confidence joints remain rejected.
- Guided calibration starts with a three-second step-back period. Measure two stable endpoints using at least six confident samples over 1.2 seconds, with no more than six degrees of spread. Require sufficient measured excursion, a consistent limb and geometry source, and supported endpoint bounds. Expire after 45 seconds. Calibration does not start or save a workout set. The coach approves the comfortable range.
- Request 720p camera capture at 30 FPS as an ideal constraint, accepting the device's actual resolution. Provide Heavy, Full and Lite choices and show the active backend and measured analysis FPS. Preserve completed counts through model fallback.
- Let coaches include the entire current studio roster at scheduling. Resolve membership on the server and validate the limit of 100 trainees. This is an enrollment limit, not a claim that a phone can simultaneously display 100 full-resolution live streams. Large rosters scroll with usable tile sizes; smaller galleries fit the available stage.
- Use flat video backgrounds, consistent borders, compact translucent nameplates and no decorative conference shadows. Keep the coach's small square anchored inside the workout camera. Maintain its stream and the trainee's tracking when resizing or minimizing.
- Rename app identity, package, authentication text, exports, GitHub and Vercel project. Use the same database and credentials. An additive nullable `videoRoomName` preserves pre-rename live rooms; new sessions persist their Geez Squad room identity. Old browser storage keys have a read-through migration on the same origin. Browser-only preferences do not automatically move between different domains.

## Verification and release acceptance

Run geometry and sequence regressions, calibration confidence/jitter/side-change tests, worker bitmap ownership and recovery tests, API membership and permission checks, native Heavy/Full browser initialization, continuous front-phone curl replay, and gallery/PiP checks at 320, 390, landscape, laptop and TV sizes. Check rendered screenshots and computed shadows/gradients. Rehearse the database change in an isolated Neon schema, then apply it before deployment. Verify the exact Git commit and CI result before promotion. Test signup, coach/trainee transport, roster enrollment, persistence and old-domain redirects on the live origin. Remove temporary verification accounts and rooms.

Physical-camera accuracy remains a separate acceptance test: compare manually labeled videos across exercises, lighting, camera views, devices and body types; measure missed/extra reps and landmark error. Synthetic trajectories validate deterministic engine behavior, not actual camera accuracy. Form and quality scores are estimates for coach review. This release does not claim perfect tracking, clinical validation, or universal zero-bug behavior.
